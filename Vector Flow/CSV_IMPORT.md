# CSV: импорт оплат

Доступен администратору: **Оплата → Шаблон CSV → Загрузить CSV**. У учредителя остаётся выгрузка; импорт изменяет записи и ему не показывается.

## Заполнение

Шаблон содержит активных учеников, их ID, выбранный период начисления, последний известный способ оплаты и справочные начисленные/оплаченные/оставшиеся суммы. Поле новой суммы пустое: шаблон нельзя случайно загрузить как повтор всех старых платежей. Дата предварительно задана концом выбранного периода — перед загрузкой проверьте её и способ оплаты.

Обязательные столбцы: `ID платежа`, `ID ученика`, `Период начисления`, `Дата оплаты`, `Сумма, ₽`, `Способ оплаты`. `Ученик` и `Комментарий` необязательны; сопоставление идёт по ID ученика, имя подтягивается из карточки. Справочные суммы никогда не становятся новыми платежами.

- Суммы: `50000`, `50000,25`, `50 000,25`; больше нуля, до двух знаков после запятой.
- Период: `2026-09` или `09.2026`. Начисление за этот период уже должно существовать.
- Дата: `2026-09-30` или `30.09.2026`.
- Способ: `Перевод` / `Наличные`.
- CSV: UTF-8 с BOM или без него, Windows-1251; разделитель точка с запятой или запятая с корректными кавычками. До2МБ и2000 строк. Многострочные комментарии и экранированные кавычки поддерживаются.

Пустая новая сумма означает «пропустить», а не нулевую оплату. Удалять остальные строки шаблона необязательно. В файле меняются только новые оплаты; это не массовое редактирование уже сохранённых записей.

## Проверка и сохранение

Предпросмотр показывает новые оплаты, общую сумму, совпадения, пустые строки и ошибки. Ни выбора файла, ни просмотра недостаточно для изменения базы. Сохранение происходит только кнопкой «Добавить оплаты».

Если хотя бы одна заполненная строка ошибочна, весь файл блокируется. Повторный ID с другими данными считается ошибкой. Совпадения по ID либо ученику/периоду/дате/сумме/способу пропускаются. Изменение комментария не даёт повторно загрузить уже учтённую оплату. Для действительно отдельных одинаковых платежей используйте ручную запись после проверки; импорт не пытается автоматически различить такие ситуации.

Перед сохранением файл повторно проверяется по текущему состоянию. Весь пакет сохраняется одной IndexedDB-транзакцией; при сбое не остаётся частичных оплат. Можно повторить подтверждение. Аннулированная импортированная запись не восстанавливается повторным чтением того же файла.

Оплаты проходят через те же команды и распределение, что ручные: меняются остатки начислений, история ученика и поступления учредителя по фактической дате. Превышение распределяется на следующие существующие начисления, остаток остаётся авансом. Редактировать или аннулировать записи можно в карточке ученика.

Готовый пример на вымышленных данных: `qa/пример-оплат-демо.csv`. Он фиксирует50тыс. для Марии Орловой за сентябрь; загружать через предпросмотр. Обычные автоматические проверки используют изолированный браузер и не меняют данные пользовательской вкладки.
