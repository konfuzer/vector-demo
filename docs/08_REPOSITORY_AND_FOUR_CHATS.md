# Организация будущего репозитория и четырёх чатов

## Что пользователь хочет буквально

**Одна общая папка на компьютере + четыре самостоятельных чата Codex:**

1. Организационный/исследовательский чат. В начале только обсуждает, показывает реальные референсы, предлагает Figma/MCP/агентов, дорожную карту и вопросы. После отдельной команды может координировать Demo Hub, общую архитектуру, сборку, маршрутизацию, тестирование и публикацию.
2. Продуктовый чат Vector Flow - файлы только в своей папке.
3. Продуктовый чат Vector Universe - файлы только в своей папке.
4. Продуктовый чат Vector Club - файлы только в своей папке.

Папки в одном репозитории. Чаты **не** создают автоматической изоляции файлов, поэтому правила владения зонами обязательны. Потенциальные конфликты корневых конфигураций решает организационный чат по согласованию.

## Предпочитаемая логическая структура (только как предмет обсуждения)

```
VECTOR DIGITAL DEMO/
  AGENTS.md
  README_START_HERE.md
  00_MASTER_CONTEXT_PROMPT.md
  docs/
  references/
  Vector Flow/
  Vector Universe/
  Vector Club/
  Demo Hub/
  [future configs - not now]
```

Названия папок с пробелами выбраны пользователем; можно предложить внутренние package names без пробелов, не переименовывая папки самовольно. Маршруты `/flow`, `/universe`, `/club` - лишь логическая идея, уточнить при выборе хостинга.

## Индивидуальный дизайн

Одна доменная зона/хостинг и один входной Hub не означают одну тему и одну базу. Каждый продукт может иметь собственную систему токенов, шрифтов, motion, IA и состояние. Фирменный бренд Vector должен оставаться узнаваемым. Общие компоненты выносить только при реальной пользе и когда они не убивают индивидуальность.

## Стек не утверждён

Пользователь не привязан к React/Vite/Next. Codex умеет их генерировать, но для выбора следует оценить производительность, простоту демонстрации на ноутбуке, возможность работать офлайн, отдельные сборки, маршрутизацию, графы навыков, 3D/видео и deploy. Предварительно React + TypeScript + Vite может быть рационален, но *не является приказом на установку*.

## Важные недостающие решения

Кому принадлежит домен? Нужен ли настоящий интернет во время встречи? Разрешена ли демонстрация локально? Будет ли большой экран или только ноутбук? Нужна ли публичная доступность по ссылке? Можно ли использовать изображения со школьного сайта? Будет ли Figma как источник истины? Кто утверждает оплату SaaS/ассетов? Будет ли настройка CMS? Нужны ли данные реальной школы? Где/как показывать дисклеймер о демонстрации?

## Изоляция и контроль

Перед будущим изменением общей инфраструктуры - коротко перечислить файлы, на которые это повлияет, и получить согласие. Не править продуктовую папку другого чата. Не запускать параллельные массовые изменения в одних файлах. Для спорных решений предлагать alternatives и trade-offs.
