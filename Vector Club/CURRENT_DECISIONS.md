## Два пути родителя и работа с обращением

Подтверждённые пользовательские возможности:

1. **«Помогите подобрать занятие»** — обращение без обязательной группы. Достаточно интересов, возраста, удобного времени и выбранного способа связи; в демо используются синтетические данные. Обычная форма доступна независимо от идеи AI-помощника.
2. **«Оставить заявку в группу»** — программа и конкретное расписание уже выбраны. Форма сохраняет этот выбор.

Оба пути создают обращение в одной очереди Club. Тип обращения («Нужен подбор» / «Заявка в группу») отличается от источника («Каталог» / «Форма подбора» / «Демонстрация помощника») и текущего статуса. Наличие примера диалога само по себе заявку не создаёт.

Реализованная детализация действий администратора:

- Взять обращение в работу и отметить контакт с родителем.
- Для обращения без группы подобрать и предложить подходящие варианты. Не занимать место до выбора конкретной группы и подтверждения намерения родителем.
- Для выбранной группы проверить места, подтвердить вариант и явно забронировать место. Запрос родителя сам по себе не гарантирует бронь.
- При отсутствии мест предложить другую группу; при невозможности записи закрыть обращение с понятной причиной. Не заменять объяснение безличной кнопкой «Отклонить».
- Отдельно отметить демонстрационную оплату уже оформленной брони. Оплата не занимает второе место.
- Отмена неоплаченной брони освобождает место. Обращение без группы вообще не меняет загрузку и денежные показатели.

Родитель видит результат, соответствующий действию: «Заявка получена», «Уточняем пожелания», «Предложены варианты», «Место забронировано», «Оплата отмечена» либо «Обращение закрыто» с причиной. Точные подписи ещё можно доработать; нельзя сообщать «Вы записаны» сразу после первичной заявки.

## Помощник — демонстрационный сценарий без модели

Прямое предложение пользователя: ненавязчивое приглашение внизу справа для родителей, которым трудно выбрать занятие. Помощник расспрашивает об интересах ребёнка, консультирует по выбору и помогает перейти к записи. Три изображения показывают дружелюбных роботов. Конкретный персонаж ещё не выбран.

Предлагаемый сценарий для обсуждения:

1. Приглашение «Не знаете, какое занятие выбрать? Помогу подобрать». Закрывается, не перекрывает запись; после закрытия в этой сессии не появляется повторно само. Каталог доступен без диалога.
2. Уточнить возраст, интересы и удобное время; при необходимости предложить указать бюджет. Имя ребёнка и другие реальные персональные данные для подбора не нужны.
3. Предложить 2–3 варианта из каталога и объяснить каждое совпадение. Не делать выводов о способностях ребёнка, не обещать «объективно лучшую» секцию, не выдумывать условия или наличие мест.
4. Если родитель выбрал конкретную группу, помощник передаёт выбор в ту же форму заявки; родитель отдельно подтверждает её отправку. Если выбор ещё не сделан, можно оставить обращение на подбор без группы и передать пожелания сотруднику. Если подходящего варианта нет — честный ответ без выдуманных предложений.
5. Заявка появляется в общей очереди администратора с источником «подбор помощника». Заявка не занимает место. Бронь и демонстрационная оплата остаются отдельными действиями.

Последнее решение пользователя: на тестовую демонстрацию модель не подключать. Допустим статичный пример диалога либо локальный сценарий, обозначенный как «Демонстрация подбора». Свободный ввод, если он не обрабатывается, не изображать работающим. Реальная AI-модель, внешний API, расходы, передача сообщений и реальные уведомления не поручены. Не выдавать демонстрационный сценарий за подключённую AI-модель.

Выбор другой группы после брони требует сначала её отменить и получить новый выбор родителя. Сброс восстанавливает только собственный набор Club.

Не заявлять буквальное попиксельное совпадение: отдельные рендеры, типографика и адаптивная компоновка отличаются от генеративного макета.
